Optimal Transport for Dataset Distance

Phil Swatton

Introduction

  • Optimal transport (OT) is the problem of finding the most efficient way to transform one distribution into another
  • Transportation theory is the subfield of mathematics concerned with this problem
  • Solutions to OT can be used to measure dataset distances
  • This is because they can define a measure of distance between distributions

Optimal Transport, Declaratively

Spaces, or How I Learned to Stop Worrying and Hate Precise Definitions

  • Textbooks on OT will talk about things like measurable space, Borel space, Polish space, Hilbert space, and reproducing kernel Hilbert space (RKHS), etc
  • For today: a space \(\mathcal{X}\) is a set of numbers or vectors where we have a sensible way to measure distances
  • Assumption: the spaces we care about have a shared distance metric \(d_{\mathcal{X}}(x, x')\)

Monge Formulation

Gaspard Monge first formalised the OT problem in 1781

Consider two spaces, \(\mathcal{X}_A\) and \(\mathcal{X}_B\), with distributions \(P_A\) and \(P_B\). The Monge formulation is:

\[ \inf_{T, T_{\#}P_A=P_B}{\int{c(x, T(x))dP_A(x)}} \]

  • \(T\) is the transport map \(\mathcal{X}_A \rightarrow \mathcal{X}_B\)
  • \(c(x, T(x))\) is the cost of transporting from \(x\) to \(T(x)\)
  • \(T_{\#}P_A=P_B\) denotes that \(P_B\) is the push-forward of \(P_A\) under \(T\)
  • The integral is over \(P_A(x)\), we integrate with respect to \(P_A(x)\)
  • If \(P_A(x)\) is a probability distribution then we could write this as \(\inf_{T, T_{\#}P_A=P_B}{\int{c(x, T(x))P_A(x)dx}}\)

Kantorovich Formulation

In 1942, Leonid Kantorovich developed a new formulation of OT.

\[ \inf_{\pi \in \Pi(P_A, P_B)}{\int{c(x,x')d\pi(x, x')}} \]

  • \(\Pi(P_A, P_B)\) is the set of all possible joint distributions \(\pi\) for \((\mathcal{X}_A, \mathcal{X}_B)\) with marginal distributions \(P_A\) and \(P_B\)
  • A minimiser \(\pi^*\) exists for every Kantorovich OT problem and is called the optimal transport plan or optimal transport coupling

What is a Metric?

In mathematical terms, a metric is any function \(d : X \times X \rightarrow \mathbb{R}\) which satisifies the following four axioms:

  1. Non-negativity: \(d(x, y) \geq 0\)
  2. Identity of Indiscernibles: \(d(x, y) = 0\) if and only if \(x = y\)
  3. Symmetry: \(d(x, y) = d(y, x)\)
  4. Triangle Inequality: \(d(x, z) \leq d(x, y) + d(y, z)\)

Wasserstein Distance

  • Until now, we have left the cost function \(c\) undefined
  • If \(c\) is a distance metric then the total cost of the Kantorovich formulation is a distance metric
  • If we choose \(c = \| x - x' \|^p\), then the total distance is known as the p-Wasserstein or \(W_p\) distance

How do I Compute OT Between Two Datasets?

A lot of the time…

For the most part, OT is not solved in the continuous case.

But there is one exception…

2-Wasserstein Solution

  • Assume \(P_A\) and \(P_B\) are both (multivariate) normal distributions
  • An anlytic solution for compurting \(W_2\) exists:

\[ W^{2}_{2}(P_A, P_B) = \| \boldsymbol{\mu}_A - \boldsymbol{\mu}_B \|^{2}_{2} + \text{tr}\left( \boldsymbol{\Sigma}_A + \boldsymbol{\Sigma}_B - 2\left( \boldsymbol{\Sigma}_{A}^{\frac{1}{2}} \boldsymbol{\Sigma}_B \boldsymbol{\Sigma}_{A}^{\frac{1}{2}} \right)^{\frac{1}{2}} \right) \]

  • \(\boldsymbol{\mu}_A\) and \(\boldsymbol{\mu}_B\) are the mean vectors for \(P_A\) and \(P_B\)
  • \(\boldsymbol{\Sigma}_A\) and \(\boldsymbol{\Sigma}_B\) are the variance-covariance matrices for \(P_A\) and \(P_B\)
  • the trace of a square matrix is the sum of its diagonal
  • \(M^{\frac{1}{2}}\) gives the matrix square root, which is defined by \(S \cdot S = M\).

If we treat our datasets as commensurate multivaiate normal distributions, we have a distance between them.

Discrete Solution

There is a defined solution to the Kantorovich formulation for discrete distributions, however. We will rewrite the formulation as:

\[ \langle \boldsymbol{C}, \boldsymbol{T} \rangle = \inf_{\boldsymbol{T} \in \Pi(\boldsymbol{a}, \boldsymbol{b})} \sum^n_{i=1} \sum^m_{j=1} \boldsymbol{C}_{ij} \boldsymbol{T}_{ij} \]

  • \(\boldsymbol{a}\) and \(\boldsymbol{b}\) are vectors representing discrete probability distributions (more on this in a moment)
  • \(\boldsymbol{T}\) is a transport matrix between \(\boldsymbol{a}\) and \(\boldsymbol{b}\)
  • \(\boldsymbol{C}\) is a cost matrix defining the cost of moving an element of \(\boldsymbol{a}\) to \(\boldsymbol{b}\) (or vice versa)
  • \(\langle \boldsymbol{C}, \boldsymbol{T} \rangle\) is the total cost.
  • this is the exact same as the Kantorovich formulation, but with the integral replaced by a double sum

Discretising Input Data

How do we obtain probability vectors \(\boldsymbol{a}\) and \(\boldsymbol{b}\)?

Treat each sample as a Dirac delta function, which has probability mass \(\frac{1}{N}\) at the sample and 0 elsewhere

\[ \delta(x-a) = 0 \; \text{for} \; x \neq a, \;\;\; \int{\delta(x-a)dx} = 1 \]

  • Each sample \(x \in \mathcal{D}\) has probability mass \(\frac{1}{N}\)
  • \(\boldsymbol{a}\) is a vector of length \(N\) with each element \(\frac{1}{N}\)
  • \(\boldsymbol{b}\) is a vector of length \(M\) with each element \(\frac{1}{M}\)
  • \(\boldsymbol{T}\) is an \(N \times M\) matrix

How does this look in practice?

Solving the Discrete OT Problem I

Because \(\boldsymbol{a}\) and \(\boldsymbol{b}\) should be marginal distributions of \(\boldsymbol{T}\), we have the constraints:

\[ \begin{align} \boldsymbol{T}\boldsymbol{1} = \boldsymbol{a}\\ \boldsymbol{T}'\boldsymbol{1} = \boldsymbol{b} \end{align} \]

A final constraint is that we cannot add or subtract mass, we can only move it. To enforce this, we have the further constraint:

\[ \forall \: i,j \; \boldsymbol{T}_{ij} \geq 0 \]

This is a linear programming problem!

Solving the Discrete OT Problem II

  • Kantorovich developed linear programming to solve optimal transport problems
  • Linear programming solvers are available in Python via scipy.optimize.linprog or the POT library
import numpy as np
import ot

rng = np.random.default_rng(42)
x_a = rng.normal(0, 1, size=(100, 2))
x_b = rng.normal(2, 1, size=(150, 2))

a = ot.unif(len(x_a))
b = ot.unif(len(x_b))
C = ot.dist(x_a, x_b)

T = ot.emd(a, b, C)
print(f"Total cost: {np.sum(T * C):.3f}")
Total cost: 8.398

Entropy Regularisation

  • Linear programming solvers scale cublically: \(O(n^3 \log n)\)
  • So we introduce entropy regularisation to make the problem easier to solve:

\[ \inf_{\boldsymbol{T} \in \Pi(\boldsymbol{a}, \boldsymbol{b})} \langle \boldsymbol{C}, \boldsymbol{T} \rangle - \epsilon H(\boldsymbol{T}) \]

where $H()$ is the entropy of the transport matrix:

\[ H\left(\boldsymbol{T}\right) = - \sum^{n}_{i}\sum^{n}_{j} \boldsymbol{T}_{ij} \log \boldsymbol{T}_{ij} \]

Sinkhorn Distance

Introducing the term means that the optimal transport matrix \(\boldsymbol{T}^*\) can now be given by:

\[ \boldsymbol{T}^* = \text{diag}(\boldsymbol{u})\boldsymbol{K}\text{diag}(\boldsymbol{v}) \]

where \(\boldsymbol{K}\) is given by

\[ \boldsymbol{K} = e^{-\boldsymbol{C}/\epsilon} \]

\(\boldsymbol{u}\) and \(\boldsymbol{v}\) are vectors chosen to satisfy the marginal constraints from before, \(\boldsymbol{T}\boldsymbol{1} = \boldsymbol{a}\) and \(\boldsymbol{T}'\boldsymbol{1} = \boldsymbol{b}\). We can find them by performing coordinate descent, setting

\[ \boldsymbol{u} \leftarrow \frac{\boldsymbol{a}}{\boldsymbol{K}\boldsymbol{v}}, \boldsymbol{v} \leftarrow \frac{\boldsymbol{b}}{\boldsymbol{K}'\boldsymbol{u}} \]

where the divisions are element-wise.

When we compute OT in this way, we call it the Sinkhorn distance.

Sinkhorn Divergence

  • Entropy regularisation forces the transport plan to be more diffuse and thus an over-estimate of actual distance
  • The Sinkhorn divergence (or debiased Sinkhorn distance) addresses this problem,:

\[ \text{SD}_{\epsilon}\left(P_A, P_B\right) = \text{OT}_{\epsilon}\left(P_A, P_B\right) - \frac{1}{2}\text{OT}_{\epsilon}\left(P_A, P_A\right) - \frac{1}{2}\text{OT}_{\epsilon}\left(P_B, P_B\right) \]

where \(\text{OT}_{\epsilon}\) is the Sinkhorn distance estimated with a given value of \(\epsilon\).

Optimal Transport Dataset Distance

The Problem We Want to Solve

  • So far we have ignored the fact datasets have labels

  • We have a cost function \(d_{\mathcal{X}}(x, x')\) for defining distance between points in the feature space \(\mathcal{X}\)

  • Imagine we have a cost function \(d_{\mathcal{Y}}(y,y')\) for defining distance between points in the label space \(\mathcal{Y}\)

  • Then we would have a distance metric between points in \(\mathcal{Z}\): \[ d_{\mathcal{Z}}(z, z') = \sqrt[p]{\left(d_{\mathcal{X}}(x, x')^p + d_{\mathcal{Y}}(y, y')^p\right)} \]

  • Unfortunately, many obvious candidates for \(d_{\mathcal{X}}\), none for \(d_{\mathcal{Y}}\)

  • E.g. how to get distance between "cat" and "car"?

The Solution

  • We do have the distribution of features underneath the labels, e.g. for the label \(y\): \(\mathcal{N}_{\mathcal{D}}(y) := \left\{x \in \mathcal{X} | (x,y) \in \mathcal{D}\right\}\)

  • For labels \(y\) and \(y'\), we can compute the optimal transport distance between these distributions using the finite samples \(\mathcal{N}_{\mathcal{D}}(y)\) and \(\mathcal{N}\_{\mathcal{D}}(y')\)

  • Our distance metric \(d_{\mathcal{Z}}\) is therefore given by:

\[ d_{\mathcal{Z}}((x,y), (x',y')) = \sqrt[p]{\left(d_{\mathcal{X}}(x, x')^p + \text{OT}(P_{y}, P_{y'})^p\right)} \]

We have now defined optimal transport dataset distance (OTDD) between two datasets \(\mathcal{D}_A\) and \(\mathcal{D}_B\):

\[ d_{\text{OT}}\left(\mathcal{D}_A, \mathcal{D}_B\right) = \inf_{\pi \in \Pi(P_A, P_B)}{\int{d_{\mathcal{Z}}(z,z')d\pi(z, z')}} \]

OTDD Implementation

  • We have several inner OT problems to solve for each pair of labels \((y, y')\) between the two datasets
  • So pre-compute pairwise label distances in advance and store in a cost matrix for the outer OT problem
  • This allows us to efficiently compute the outer OT problem without having to recompute the inner OT problems each time
  • We can compute the outer OT problem via linear programming, including via Sinkhorn distance or divergence, given the cost function \(d_{\mathcal{Z}}\) defined above
  • Microsoft Research have released a Python implementation of OTDD
  • But this is old and somewhat broken, so see the ARC version with some masking tape at https://github.com/alan-turing-institute/arc-otdd/tree/main
